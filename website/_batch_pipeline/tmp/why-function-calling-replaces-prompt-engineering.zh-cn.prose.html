函数调用已把企业 AI 的错误率相比提示词方案降低了 72%，同时消除了对脆弱提示工程工作流的需求。与其把指令编码在 LLM 可能误解的自然语言提示词里，函数调用提供了模型可以可靠调用的结构化接口。这个范式转变正在改变企业构建 AI 应用的方式——从"编写和维护提示词"的纪律，转向"设计接口"的纪律。本文解释转变为何发生、对你的架构意味着什么，以及如何安全地完成过渡。

转变在模型厂商设计平台的方式中清晰可见。每一家主流 LLM 厂商现在都提供原生函数调用——把结构化工具调用当作一等公民——因为市场上要求最高的客户，也就是在模型之上构建代理的企业，用生产负载投了票。提示工程是第一代接口：在模型还小、工具层还薄的时候有用，但本质上是对"模型无法被可靠告知该做什么"的一种变通。函数调用用契约取代了变通，而契约是企业能治理、能测试、能审计的东西。

函数调用取代提示工程的 5 大原因

  1. 结构化输出保证。提示工程产生需要解析的自由文本响应。函数调用返回带定义 schema 的结构化 JSON 对象。这消除了困扰企业集成的解析错误，并把后处理代码减少 80%。
  2. 确定性的工具使用。"如果用户问销售，就查询销售数据库"这类提示是概率性的——能否生效取决于措辞和模型版本。函数调用定义精确的工具签名：模型知道需要哪些参数、接受哪些类型、每个工具返回什么。工具调用变得确定、可测试、可重复。
  3. 跨多个工具扩展。通过提示工程管理五个以上工具，需要越来越复杂的提示词，而提示词越大性能越差。函数调用自然扩展：每个工具有自己的 schema，模型按查询选择正确的组合。模型上下文协议（MCP）通过标准化的工具发现进一步延伸这一点，让代理能找到并调用从未被明确告知的工具。
  4. 消除提示维护债务。企业提示词库积累了数百个变体，模型一更新就失效。函数调用接口像任何 API 契约一样被版本化、文档化、可测试。它们经受得住模型更新，因为接口是契约性的而非语言性的：schema 不变，行为就不变。
  5. 支持多步代理工作流。复杂的企业任务需要串联多个工具调用——查数据库、发邮件、更新 CRM 记录。函数调用提供了让多步代理可靠且可审计的结构化编排层，每一次调用都对照 schema 记录，而不是埋没在自由文本里。

函数调用与提示工程

提示工程在创造性任务、语气调整和输出天然开放的一次性交互中仍有价值。对于要求可靠性、结构化输出和工具集成的企业工作流，函数调用是更优的方法。两者互补，但服务于根本不同的目的：提示词塑造语言，函数调用塑造行为。试图用提示词去做函数调用的事，就像在需要 API 契约的地方用一份样式指南。

对比在失败代价最高的地方最鲜明。一位财务分析师让模型"算一下收入然后放进报告"，不同日子得到不同结果；同一位分析师调用一个带显式参数的、经过验证的收入函数，每次得到同一个契约定义的结果。在伯克利函数调用排行榜上，顶级模型从 2023 年底约 60% 的工具调用准确率，提升到 2025 年年中超过 92%——让提示词变得必要的可靠性问题，正在平台层被工程化掉。

这些都不意味着提示词消失——而是它的角色收窄。系统提示词仍然设定语气、护栏和风格；少样本示例仍然在开放式任务中示范边缘案例。分界线是行为：任何必须可靠发生的事情——一次工具调用、一次数据转换、一个结构化响应——都属于函数定义，而不是散文。工程经验法则很简单：如果你发现自己在写提示词去强制一个具体的输出形状或一次具体的工具调用，把它转成函数，像代码一样测试。每一次转换，都把风险从不可预测的语言层，移到可测试的契约层。

模型更新时提示词为什么会失效？

因为提示词是语言产物，而语言不是契约。当模型厂商发布更新时，每个短语之下的概率都会移动：上季度可靠触发工具调用的指令，现在可能产生不同的解读、一次拒绝，或一个幻觉出来的替代品。企业提示词库——跨团队通常积累 400 个以上变体——继承了这种不稳定性，每一次升级都变成对从未被正式指定的行为做回归测试。

函数调用反转了这个关系。接口由 schema 定义——参数名、类型、必填字段、返回契约——模型被训练去遵守它，而你的集成代码可以验证它。模型更新时，schema 不变，行为就不变；升级风险从"我的提示词还能用吗？"变成"新模型至少能像旧模型一样处理这个 schema 吗？"这是一个可测试、有边界的问题。提示维护是跑步机；schema 版本管理是契约。这就是企业正在删除提示词库、而不是重组它们的原因。

这对你的数据平台意味着什么？

它意味着工具层成为产品。如果函数调用是可靠接口，那么你的 AI 质量取决于你的工具质量：它们的 schema、它们的治理、它们的可观测性。一个对话式 BI 代理，只与其能调用的数据工具一样可信——收入函数、群组查询、预测端点——而这些工具每一个都需要一个契约、一个负责人、一套测试。这正是 MCP 重要的地方：一个标准协议意味着工具跨模型可发现、可版本化、可替换，所以平台不必在模型变化时重建。

战略含义是，AI 团队应该把精力花在工具设计上，而不是提示词手艺上。一个设计良好的函数调用面——精确的 schema、清晰的参数验证、丰富的返回类型——取代一整座脆弱提示词的图书馆，交付更低的错误率、更好的可观测性、更轻松的治理。审计线索也改善：每一次函数调用都是结构化数据，所以每一次 AI 行动都可以被记录、查询、复核。对受监管企业，那就是"可以解释的 AI"与"只能祈祷的 AI"之间的区别。

治理故事补全了这幅图景。有了函数调用，每一次 AI 行动都是一个结构化事件：哪个函数、哪些参数、哪个模型、哪个响应。这种结构以自由文本提示词永远做不到的方式，自然流入审计系统、审批工作流和用量分析。当监管者问上个月 AI 做了什么，答案是结构化日志上的一次查询，而不是对聊天记录的一场通读。完成这一转变的企业报告，合规姿态作为架构改变的副产品改善了——不是因为他们加了控制，而是因为结构化接口让控制从一开始就变得可能。
