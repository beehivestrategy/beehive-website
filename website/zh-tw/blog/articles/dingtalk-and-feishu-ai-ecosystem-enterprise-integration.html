釘釘與飛書 AI 生態系：中國企業整合指南

蜂
蜂啟諮詢 · 2026年6月25日 · 5 分鐘閱讀
中國企業 IM 的兩大巨頭 釘釘的 AI 助手生態系 飛書的 AI 能力 MCP 與中國 IM 平台的相容性 BI 部署的平台比較 實務實施步驟 核心要點

釘釘和飛書早已遠遠超越了通訊軟體的範疇。到 2026 年，它們已成為數百萬中國企業的中樞神經系統——兩個平台都在建構日益精密的 AI 生態系。對於希望部署對話式 BI 的組織而言，了解如何與這些平台整合已非可選——它是在中國的主要部署模式。

核心要點： 釘釘與飛書各自建構了豐富的 AI 生態系統，透過 MCP 協議整合，企業可在不更換現有 IM 平台的情況下，將對話式 BI 工具無縫嵌入日常工作流程。

中國企業 IM 的兩大巨頭

中國企業協作市場由兩個平台主導，每個平台都背靠一家科技巨頭：

  • 釘釘（阿里巴巴集團）：擁有超過 7 億個人使用者和 2500 萬企業組織，釘釘是中國部署最廣泛的企業 IM 平台。它在製造業、零售業和政府部門具有特別強的滲透率。
  • 飛書 / Lark（字節跳動）：飛書（國際上稱為 Lark）已迅速獲得市場佔有率，特別是在科技公司、網際網路企業和知識密集型產業中。其文件優先的設計理念和強大的第三方整合生態系使其在初創公司和規模化企業中深受歡迎。

釘釘的 AI 助手生態系

釘釘透過幾項關鍵舉措大力投資其 AI 能力：

  • 釘釘 AI 助手平台：於 2023 年推出並在 2026 年大幅擴展，該平台允許企業建構可在釘釘聊天串中運作的自訂 AI 助手。它支援與阿里巴巴通義千問（Qwen）LLM 以及第三方模型的整合。
  • 企業智慧體市場：一個企業可以發現、部署和分享預建 AI 智慧體的市場。截至 2026 年中，該市場託管了數千個涵蓋人力資源、財務、營運和分析功能的智慧體。
  • 基於動作的架構：釘釘的 AI 助手框架支援「動作」——AI 可以根據使用者請求觸發的獨立 API 呼叫。這在架構上類似於 MCP 的工具呼叫範式，使釘釘成為 MCP 驅動對話式 BI 的天然契合平台。

飛書的 AI 能力

飛書採取了不同但同樣強大的方法：

  • 飛書智慧夥伴（飛書 Bot 2.0）：飛書的 AI 機器人框架支援多輪對話、跨聊天串的上下文感知以及呼叫外部 API 的能力。它支援字節跳動的豆包模型以及其他國內和國際 LLM。
  • 飛書 AnyCross：一個將飛書連接到 300 多個企業應用程式的整合平台。AnyCross 提供 ERP、CRM 和資料庫系統的預建連接器——補充了 MCP 的資料來源連接性。
  • 文件 AI：飛書在協作文件方面的優勢延伸到 AI 驅動的文件分析、自動報告生成和從電子表格中提取資料——這些能力與對話式 BI 的臨時分析自然搭配。

MCP 與中國 IM 平台的相容性

模型上下文協議（MCP）本質上是一個定義 AI 模型如何存取資料的客戶端-伺服器協議。將 MCP 與釘釘或飛書整合需要一個橋接層——一個在 IM 平台的機器人框架和 MCP 伺服器之間進行轉換的適配器。運作方式如下：

  1. IM 機器人接收使用者查詢，在釘釘群組聊天或飛書討論串中。
  2. 橋接適配器（由 蜂啟諮詢 或您的整合團隊開發）透過 IM 平台的 webhook 或 API 接收訊息。
  3. LLM 處理查詢並確定需要呼叫哪些 MCP 伺服器來取得相關資料。
  4. MCP 伺服器執行對企業資料來源（MySQL、Snowflake、SAP 等）的查詢並回傳結構化結果。
  5. LLM 格式化回應——包括圖表、表格或自然語言摘要——橋接適配器將其回傳到 IM 對話中。

釘釘和飛書都支援豐富的訊息格式（卡片、互動元素、圖表嵌入），這意味著對話式 BI 回應可以包含視覺格式化的資料視覺化，而不僅是純文字。

實務實施步驟

對於希望透過釘釘或飛書部署對話式 BI 的企業，實施路徑如下：

  1. 選擇 IM 平台。如果您的組織已經標準化使用其中一個，從該平台開始。如果跨兩個平台運營，具有平台特定適配器的統一後端是推薦的架構。
  2. 註冊企業機器人。透過釘釘開放平台或飛書開發者控制台建立機器人應用程式。配置 webhook 端點和權限範圍。
  3. 部署 MCP 橋接。部署連接您的 IM 機器人與 MCP 伺服器基礎設施的橋接適配器。這處理訊息路由、身份驗證和回應格式化。
  4. 配置資料連接器。為您關鍵企業資料來源設定 MCP 伺服器——ERP、CRM、財務系統和資料倉儲。
  5. 測試與迭代。從 10-20 名高階使用者開始試點。在擴展到全組織之前，收集關於查詢準確率、回應速度和使用者體驗的回饋。

核心要點

釘釘和飛書不僅僅是通訊平台——它們是中國企業工作的作業系統。透過這些平台部署對話式 BI，意味著在使用者已經工作的地方與他們會面，消除導致獨立分析工具失敗的採用障礙。

常見問題

MCP（Model Context Protocol）作為開放標準，讓 AI 助手能夠直接連接企業數據源和應用程式。透過標準化的介面，企業無需為每個 AI 模型建立自訂連接器，大幅降低整合成本和複雜度。
釘釘以工作流程自動化和任務協作為核心，飛書則以文件協作和即時通訊整合見長。兩者都在 AI 能力上大量投資，釘釘專注於企業自動化，飛書則整合 AI 助手進行智慧搜尋和內容生成。
企業應評估現有工具棧、員工使用習慣、數據安全需求和 AI 能力需求。關鍵考量包括 MCP 相容性、數據主權控制、API 開放程度，以及平臺是否支援自訂 AI Agent 部署。
